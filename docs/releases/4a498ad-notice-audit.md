## Python и требование к процессору

В AppImage находится CPython `3.12.14`, собранный для `x86_64_v2`.
Совпали `.text`, `.rodata` и `.note.gnu.build-id` с официальным архивом
PBS `cpython-3.12.14+20260901-x86_64_v2-unknown-linux-gnu-install_only_stripped.tar.gz`.
SHA-256 этого upstream-архива:

```text
ebd95954e6fd469a107507f491104ff3412e8b3bc0bc3177f385b60e5b7555b8
```

Конфигурация Python из самого AppImage дополнительно содержит
`-march=x86-64-v2`. Поэтому обозначения Linux x86_64 и проверки GLIBC сами
по себе недостаточны для обещания поддержки всех старых x86_64 процессоров.

Для исследования лицензий получен полный PBS-архив того же релиза для
базового `x86_64`, проверенный по GitHub release digest. Из него сохранены
`PYTHON.json` и тексты `python/licenses/`. Его libpython не совпадает с
вариантом `x86_64_v2`; он не подменялся в AppImage. Лицензионные материалы
этого архива обозначены как reference. Точный состав статических зависимостей
нужно окончательно связать с метаданными варианта v2.

Документация [python-build-standalone](https://gregoryszorc.com/docs/python-build-standalone/main/running.html#licensing)
указывает на отдельные лицензионные метаданные и тексты зависимостей. Один
`python3.12/LICENSE.txt` не следует считать их полным реестром.

## Нативные библиотеки

Для 31 из 35 библиотек непосредственно в `usr/lib/` найдены соответствующие
Ubuntu copyright-файлы. В исходном AppImage отсутствуют следующие четыре.

| Библиотека | Установленный источник восстановленного copyright |
| --- | --- |
| `libcap.so.2` | `libcap2` версии `1:2.44-1ubuntu0.22.04.3` |
| `libcrypt.so.1` | `libcrypt1` версии `1:4.4.27-1` |
| `liblzma.so.5` | `liblzma5` версии `5.2.5-2ubuntu1.1` |
| `libpcre.so.3` | `libpcre3` версии `2:8.39-13ubuntu0.22.04.1` |

Пакеты загружены из официального Ubuntu archive и распакованы без установки.
У каждой библиотеки совпали Build ID, `.text` и `.rodata`. Copyright-тексты
сохранены в отдельном дополнении. Наличие этого дополнения не изменяет
содержимое уже собранного AppImage.

Часть включённых copyright-файлов ссылается на
`/usr/share/common-licenses`, которого в AppDir нет. Для комплекта нужны
полные тексты применимых лицензий, а не только ссылки на каталог хоста.
Пакетные copyright-файлы могут описывать также утилиты и другие файлы
исходного пакета. Нельзя автоматически приписывать все перечисленные в них
лицензии каждому включённому `.so`.

| CPython | Кроме PSF-лицензии нужны сведения о статически включённых зависимостях. Reference PBS metadata перечисляет OpenSSL, libffi, bzip2, libedit/ncurses, mpdecimal и другие компоненты | Сверить метаданные точного v2-архива и сохранить применимые тексты, включая отдельный `_dbm`/Berkeley DB |

| KaTeX fonts | 20 TTF содержат copyright и указание на SIL OFL 1.1. Полный текст OFL в `NOTICES.Z` не найден | Включить OFL 1.1 и copyright/Reserved Font Names из самих шрифтов |
| Реестр Tokenlogue | Корневой `THIRD_PARTY_NOTICES.md` описывает только прямые Python-зависимости | Добавить индекс фактических компонентов, файлов лицензий и источников |

Upstream [type2-runtime](https://github.com/AppImage/type2-runtime/tree/caf24f9f712084686bfc24a70b75e50df0aefb9c)
перечисляет статически включённые библиотеки.
[dart-bridge](https://github.com/flet-dev/dart-bridge) имеет собственную MIT
лицензию. Общая лицензия serious_python не заменяет автоматически эти записи.
