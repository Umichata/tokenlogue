# Tokenlogue 0.1.0: Linux preview 1

Статус на 9 сентября 2026 года: подготовка тестового релиза. Предлагаемое
имя тега: `v0.1.0-linux-preview.1`; тег и GitHub Release ещё не созданы.
Версия внутри приложения остаётся `0.1.0`.

Сверка AppImage завершена. Архив, контрольные суммы и provenance совпали.
Проверка лицензий выявила пропуски в исходном AppImage, часть текстов уже
восстановлена отдельно. Полный комплект сторонних notices и исходников ещё
не завершён. Публикация этого кандидата пока не подготовлена.

## Назначение сборки

Тестовая Linux x86_64 сборка Tokenlogue предоставляет локальные чаты,
сохраняемые черновики, вход по PIN, защищённое хранение API-ключа и лимиты
токенов и расходов. Она использует GTK3 и desktop-модули целевой ОС, включая
GVfs и IBus. Python и Flutter включены в AppImage.

[Инструкция запуска](../linux-appimage.md) описывает системные требования,
проверку контрольной суммы и режим запуска без FUSE.

## Подтверждённые проверки

- Успешная Ubuntu 22.04 сборка с обязательными проверками inventory по
  `uv.lock`, metadata, переносимых RUNPATH и отсутствия неожиданных
  неразрешённых ELF-зависимостей.
- Пройдены ABI-ограничения `GLIBC <= 2.35`, `GLIBCXX <= 3.4.29`,
  `CXXABI <= 1.3.13`. При отдельном статическом анализе всех 50 ELF в
  извлечённом AppDir максимумы требуемых undefined versioned symbols
  составили `GLIBC_2.34`, `GLIBCXX_3.4.29` и `CXXABI_1.3`.
- Успешная повторная упаковка с проверкой побитового совпадения внутри
  build-запуска. Воспроизводимость между разными runner images не установлена.
- Матрица Ubuntu 22.04, Ubuntu 24.04 и Fedora 44: Xvfb, программный рендеринг,
  временные данные и keyring, отключённая сеть, обнаружение окна и cleanup.
- Все три предоставленных `desktop-modules*.json` содержат `PASS`, пустые
  списки ошибок и системные пути desktop-библиотек. GVfs и IBus загружаются.
- Ручные проверки Linux Mint 22.3 Cinnamon/X11: ввод, буфер обмена и
  восстановление черновиков работают. В двух предоставленных логах нет
  прежних ошибок `g_task_set_static_name`, загрузки GVfs/IBus или traceback.

Ранее обычное FUSE-монтирование было отдельно подтверждено для файла
`7c3976a`. Этот исторический результат не следует выдавать за новую проверку
`--appimage-mount` файла `4a498ad`. Для новой сборки сообщены успешные ручные
запуски; предоставленные stderr-логи сами по себе не фиксируют режим
монтирования, выбранный GPU или код завершения.

## Ограничения

- Процессор должен поддерживать x86-64-v2. Секция кода, констант и Build ID
  включённого libpython совпали с CPython 3.12.14 из PBS 20260901 для
  `x86_64_v2`; в сохранённой конфигурации есть `-march=x86-64-v2`.
  Прежнее предположение о Python 3.12.13 к этому файлу не относится.
- AppImage не подписан; автоматическое обновление отсутствует.
- GTK3, графический стек и Secret Service предоставляет целевая ОС.
  Проверка трёх контейнерных сред не означает поддержку всех дистрибутивов,
  Wayland, desktop-сессий и видеодрайверов.
- В ручном stderr остаются предупреждения Flutter `FlutterEngineRemoveView`
  и `FlBinaryMessenger without an engine`. Видимого влияния на проверенные
  функции не обнаружено; исправление этих сообщений не заявляется.
- Содержимое истории и черновиков в SQLite дополнительно не шифруется.
- Первоначальное доверие к закреплённым build tools основано на release
  assets и SHA-256 (TOFU); наличие подписанного provenance не заявляется.
