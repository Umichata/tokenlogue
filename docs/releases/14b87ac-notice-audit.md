# Сверка AppImage 14b87ac и реестра notices

Дата проверки 10 сентября 2026 года. Проверены предоставленные архивы
`tokenlogue-linux-diagnostic-14b87ac.zip` и
`verified-appimage-34439720271.zip`. Публичные сведения о запусках, заданиях
и артефактах получены через GitHub API. При аудите использовалось извлечение
AppImage. GUI приложения, пользовательская БД и SecureStorage не запускались.
Байты исходных ZIP и AppImage сохранены.

`userspace`. Подробные архивы отчётов трёх userspace отдельно не анализировались.
Ручная стабильность нового файла подтверждена сообщением пользователя.

| Проверка | Результат |
| --- | --- |
| Обычные файлы в извлечённом AppDir | 1363 |
| Символические ссылки | 3, относительные, цели существуют внутри AppDir |
| ELF внутри AppDir | 50. Отдельный AppImage runtime в это число не входит |
| Реестр notices | 75 компонентов, 85 объектов, 207 хешируемых файлов |
| Объекты реестра | 50 ELF, 13 distribution METADATA и 22 файла шрифтов |
| Проверка каждого хеша | PASS |
| Соответствие реестра отчёту CI | Встроенный `notices.json` побайтно совпал с `notices-manifest.json` |
| Незарегистрированные проверяемые объекты | Отсутствуют |

| RUNPATH | Только переносимые записи относительно `$ORIGIN` |
| JNI/JVM и удалённый Tcl/Tk | Запрещённые файлы и зависимости не обнаружены |

ABI отдельно вычислен через `objdump -T` только по undefined versioned
symbols всех 50 ELF. Динамические секции прочитаны через `readelf -d`.
Результат совпал с `elf-abi.txt` runner и укладывается в прежние пределы.
Приложение и его ELF при этой статической проверке не запускались.

Входной runtime совпал с закреплённым SHA-256
`d30a3ba1388ef57be73faabf606e0d326682f48c87f666106a3c8d6b35b58b4f`.
Первые 944632 байта готового AppImage отличаются от него только содержимым
поля `.digest_md5`, которое заполняется при упаковке. Код runtime совпал.

## Что исправлено после прежних сборок

| Исторический результат | Текущее подтверждение |
| --- | --- |
| В `4a498ad` отсутствовала часть notices | Новый индекс включает Ubuntu copyright, common-licenses, Python runtime и packages, Flutter, dart-bridge, AppImage runtime и шрифты |
| Эталон bridge 1.8.0 не совпал с разрешённой сборкой | В реестре закреплён bridge 1.9.0. Notices прошли проверку в AppDir и AppImage |
| В `239ea91` сырой pubspec.lock содержал абсолютный путь runner | Во вложенной аудиторской копии локальный путь относительный. Исходный lock и его хеш сохранены |
| Отсутствующий `rg` пропускал часть финальных проверок | В обоих логах упаковки есть `Staged content checks: PASS`, сообщений `rg: command not found` нет |

Корневой `THIRD_PARTY_NOTICES.md` репозитория не изменялся. В AppImage две
его копии являются сгенерированным индексом. Полнота notices проверяется по
конкретным объектам и контрольным суммам реестра.

## Подлинный Flutter lock

SHA-256 `flutter-pubspec.lock` из build-отчёта:

```text
1522626ef038c65fd2fc10561be647c9abb979d87fae15c6d027e8e1959064d0
```

Он совпал с `resolved_packages_source_sha256` компонента
`flutter-and-plugins`. Преобразование выполнено повторно на предоставленном
исходном lock, и результат побайтно совпал со встроенной копией.

Сохранены все 153 зависимости, версии, hosted SHA-256 и остальные поля.
Изменены только `description.path` зависимости `flet_secure_storage` на
`../flutter-packages/flet_secure_storage`, признак `relative` на `true` и
поясняющая шапка. Путь отсчитывается от сгенерированного Flutter-проекта.
Копия в каталоге лицензий помечена как аудиторская.

Техническое покрытие notices и целостность файлов подтверждены. Состояние
отдельного комплекта исходников и материалов пересборки осталось прежним:

REVIEW_REQUIRED: license collection is not a corresponding-source archive

Следующая работа привязана к фактическому реестру этого файла.

Готовность исходного комплекта нужно фиксировать отдельным манифестом с
проверенными SHA-256. Наличие лицензий, списка версий или PBS-архива само
по себе не меняет текущий `REVIEW_REQUIRED`. При проверке Ubuntu copyright
следует учитывать, что один файл описывает также части исходного пакета,
которые могут отсутствовать в AppImage.
