# Запуск Tokenlogue AppImage в Linux

Эта инструкция относится к тестовой сборке приложения `0.1.0` из коммита
`4a498adfdb175104fe12acfea2b6a839f839852b`:
`Tokenlogue-0.1.0-4a498ad-x86_64.AppImage`.

## Требования

- Linux x86_64 с графической сессией и процессором с поддержкой x86-64-v2.
  В этом AppImage используется CPython 3.12.14, собранный для x86_64_v2.
  Эталон системных библиотек для сборки приложения: Ubuntu 22.04.
- GTK3 и её системные зависимости: GLib/GIO, Pango/Cairo, GdkPixbuf и
  библиотеки доступности. GTK4 не заменяет GTK3.
- Рабочие графические библиотеки и драйверы ОС.
- Пользовательская D-Bus-сессия и Secret Service, например GNOME Keyring,
  для хранения API-ключа. Включённый в AppImage клиент libsecret сам по себе
  не предоставляет такое хранилище.
- Для обычного запуска: работающий FUSE. Если он недоступен, используйте
  описанный ниже режим распаковки.

Python, uv, Flutter SDK и инструменты компиляции для запуска AppImage не нужны.
Для общения с моделями нужен доступ к OpenRouter и API-ключ; локальные
проверки запуска не отправляют запросы к моделям.

## Где находится приложение

В распакованных результатах матрицы `34345861706` откройте папку
`verified-appimage-34345861706`. Она содержит файл AppImage,
`SHA256SUMS` и `provenance.json`. Остальные папки матрицы содержат отчёты
проверок соответствующих дистрибутивов.

Если артефакты лежат в общей папке, откройте терминал в этой папке и выполните:

```bash
cd verified-appimage-34345861706
sha256sum --check SHA256SUMS
```

Ожидаемый результат:

```text
Tokenlogue-0.1.0-4a498ad-x86_64.AppImage: OK
```

Продолжайте после результата `OK`. При несовпадении заново получите AppImage
и исходный `SHA256SUMS` из одного проверенного артефакта. Не заменяйте
ожидаемую сумму результатом вычисления для повреждённого файла.

Для этого конкретного файла проверены размер `32 627 192` байта и SHA-256:

```text
f96616413d7bdc22fb670d7d65b6add15f18fa415e756775ea5d3bf04540457b
```

## Обычный запуск

В той же папке:

```bash
chmod u+x ./Tokenlogue-0.1.0-4a498ad-x86_64.AppImage
./Tokenlogue-0.1.0-4a498ad-x86_64.AppImage
```

Запускайте приложение от обычного пользователя. Установка через системный
менеджер пакетов для самого AppImage не требуется. После выдачи разрешения на
выполнение файл также можно открыть через файловый менеджер, если он
поддерживает запуск исполняемых файлов.

AppImage можно хранить в удобной папке. Автоматическое добавление ярлыка в
меню приложений этой сборкой не выполняется.

## Запуск без FUSE

```bash
./Tokenlogue-0.1.0-4a498ad-x86_64.AppImage --appimage-extract-and-run
```

Этот режим временно распаковывает содержимое и запускает приложение. В
каталоге временных файлов должно быть достаточно места для распакованного
образа. Подробности приведены в
[документации AppImage](https://docs.appimage.org/user-guide/troubleshooting/fuse.html).

## Данные и обновление

История и черновики находятся в локальной SQLite-базе в каталоге данных
приложения, отдельно от файла AppImage. Текст базы дополнительно не шифруется;
PIN ограничивает вход через интерфейс. API-ключ хранится отдельно через
SecureStorage/Secret Service.

Автоматического обновления нет. Для замены версии закройте приложение,
проверьте SHA-256 нового файла и запустите его под той же учётной записью ОС.
Замена AppImage не удаляет каталог данных. Совместимость базы с произвольными
более старыми версиями приложения не проверена.

## Что проверено

| Среда | Проверка |
| --- | --- |
| Ubuntu 22.04 | Сборка, проверки зависимостей и ABI, изолированный запуск; отдельно запуск того же файла в контейнере и загрузка GVfs/IBus |
| Ubuntu 24.04 | Запуск того же файла в контейнере и загрузка GVfs/IBus |
| Fedora 44 | Запуск того же файла в контейнере и загрузка GVfs/IBus |
| Linux Mint 22.3 Cinnamon/X11 | Ручные запуски; ввод текста, буфер обмена, сохранение и восстановление черновиков |

Проверки в контейнерах используют Xvfb и программный рендеринг. Они не
заменяют проверку реальной Wayland-сессии и отдельных видеодрайверов.
Сводка запусков и известные ограничения находятся в
[карточке тестового релиза](releases/v0.1.0-linux-preview.1.md).

## Известные сообщения в терминале

В ручных запусках остались сообщения Flutter с `FlutterEngineRemoveView` и
`FlBinaryMessenger without an engine`. Видимых сбоев ввода, буфера обмена и
черновиков при этих проверках не обнаружено. Сообщения ещё не устранены.

Ошибки `undefined symbol: g_task_set_static_name`, загрузки GVfs и IBus из
предыдущей сборки в новых ручных логах отсутствуют. Если они появятся вновь,
сохраните вывод терминала, название AppImage и версию ОС для диагностики.
