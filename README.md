# Tokenlogue

Tokenlogue — защищённый мультиплатформенный клиент OpenRouter с локальной
историей диалогов и настраиваемыми лимитами токенов и расходов.

## Возможности

- локальный вход по четырёхзначному PIN;
- хранение API-ключа в платформенном SecureStorage;
- выбор бесплатного или платного режима и модели для каждого чата;
- несколько локальных чатов с полной историей сообщений;
- отдельный автоматически сохраняемый черновик каждого чата с восстановлением
  после переключения и перезапуска;
- лимиты токенов, максимальной длины ответа и расходов для отдельных чатов;
- консервативное резервирование бюджета до завершения запроса;
- безопасная обработка неопределённого результата запроса без автоматического
  освобождения резерва.

История сохраняется в приватной SQLite-базе приложения без дополнительного
шифрования содержимого. PIN в открытом виде не хранится. API-ключ хранится
отдельно через защищённое хранилище платформы.

Черновики хранятся в той же локальной SQLite отдельно от истории. Они не
передаются модели и не расходуют лимиты. Черновик очищается при успешной
локальной регистрации отправки только для отправленной ревизии текста;
ошибки предварительной проверки и отмена платного запроса его сохраняют.

## Требования

- Python 3.12;
- [uv](https://docs.astral.sh/uv/).

Установка окружения и локальный запуск:

```bash
uv sync
uv run flet run
```

Запуск тестов:

```bash
uv run python -m unittest discover -s tests -v
```

## Платформы

Целевые платформы проекта: Linux, Windows и Android. Готовые установочные
пакеты пока не опубликованы.

## Linux desktop integration

Файлы в `packaging/linux/` описывают launcher и запись каталога приложений для
будущих Linux-пакетов. Диагностический Linux bundle собран; DEB и RPM пока не собраны;
наличие этих метаданных не означает наличие готового установочного пакета.
Команды установки и запуска пока не документируются.

Диагностическая AppImage-инфраструктура хранится в
`packaging/linux/appimage/`. Результаты находятся в `build/appimage/` и в
диагностических artifacts GitHub Actions. Они не подписаны и пока не
предназначены для широкого распространения.

Ручной workflow `build-linux.yml` уже успешно выполнил сборку и автоматическую
проверку запуска на Ubuntu 22.04. Эта система — ABI baseline с потолком
`GLIBC_2.35`; состав Python-пакетов проверяется относительно `uv.lock`.
По сообщению пользователя, в AppImage сборки `7c3976a` на Linux Mint вручную
проверены черновики при переключении чатов и после перезапуска. Ограничения
старой локальной Mint-сборки не относятся автоматически к новым CI-артефактам.

Отдельный ручной `test-linux-appimage.yml` проверяет один существующий артефакт
в Ubuntu 22.04, Ubuntu 24.04 и Fedora 44. Матрица `34011565339` прошла для
сборки `7c3976a`. Для каждого нового артефакта нужны точный ID успешного
build-запуска и полный SHA приложения; исходный файл проверяется по SHA-256,
не пересобирается и не подписывается. Контейнерная проверка userspace не подтверждает обычный
FUSE-запуск, Wayland, аппаратные драйверы или все desktop-окружения.

AppImage использует системную GTK3 и её зависимости, чтобы GVfs, IBus и
другие desktop-модули загружались с совместимой GLib. Эти runtime-пакеты должны
присутствовать в целевой ОС. Новая проверка матрицы требует успешной загрузки
GVfs и IBus; результат сохраняется в `desktop-modules.json`. Изменение упаковки
требует новой сборки и проверки нового артефакта во всех трёх средах.
Эти диагностические артефакты не являются широким публичным релизом.

OpenRouter является сторонним сервисом. Проект Tokenlogue не связан с
OpenRouter и не аффилирован с ним.
